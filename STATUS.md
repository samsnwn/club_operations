## Risks

- **Stubs mistaken for delivered automation:** import runs only when someone clicks it (no scheduler) and export is a placeholder; keep STATUS, docs and UI copy explicit so nobody expects invoices to flow automatically or reach the sheet.
- **Extraction quality:** generic regex plus Tesseract is unproven on real scans; if accuracy is poor, supplier templates or OCR tuning are needed before automation is worth enabling.
- **Drive access setup:** the owner must share the invoice folder with the service account; until then Import fails with a clear 502 message.
- **OCR/cloud trade-off:** if most invoices are scans, local-only extraction may be too weak; cloud OCR raises local-first/GDPR questions the owner must decide (owner currently chose Tesseract only).
- **Excel file locking/monolith drift:** mitigated by the Google Sheets API path; and by keeping the sheet as an output artifact with SQLite records as source of truth.
- **Plan-vs-reality drift:** the plan describes the full platform while only the invoice review demo and auth exist; avoid ambiguity by keeping STATUS.md and docs/next-steps.md current.
- **Production gap:** dev compose only; production overrides, HTTPS and backups are still missing; sign-in throttling exists but is in-memory and needs `--proxy-headers` behind a reverse proxy. The invoice service is now loopback-bound in dev and refuses the default token outside development, but production must still set a unique token and keep `:8081` unpublished.
